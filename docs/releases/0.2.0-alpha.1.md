# LoopForge 0.2.0-alpha.1 — FL Studio test candidate

Status: Windows test alpha. A published asset is available only when the Native plugin workflow successfully builds/tests and uploads it. FL Studio compatibility remains unverified. Application version remains0.2.0; package commit SHA identifies this alpha. No main merge is required to test the feature branch.

Includes native offline4/8/16bar Composer, RU/EN directions and deterministic seeds, seven Auto/manual mood axes, per-track note editing/quantize/Undo/Redo, project/recipe persistence, basic native preview and type1 MIDI export. No runtime Node service is needed for Composer.

Use FL-STUDIO-TEST.md for installation, wrapper MIDI port routing, export/import fallback and the host test record. Do not infer FL compatibility from Linux or unit tests. The first test uses offline generation and exported MIDI; Composer drag, scoped regeneration, remaining controls and seamless standalone looping are incomplete. Preview is64voice sine/percussion, not GM playback. Old longer documents remain readable/exportable; new generation is capped at16bars.

Known acceptance gaps: actual Windows build/scan/FLP reload/device timing, full workspace memory/slow IO/listening, and open errors.md findings. Prior deferred UI/seed-race minors remain documented in task.md. Binaries are unsigned/unverified unless the specific package manifest says otherwise. Open distribution was selected: combined native work uses AGPLv3 with preserved MIT notices and the GPLv3 SDK option; full license texts and committed source archives are included. Build/source correspondence still requires verification. Never label a Linux ZIP as Windows or distribute synthetic PE test fixtures.

Release delivery requires a current successful Windows build+tests, candidate ZIP and SHA256SUMS, recorded source commit, dependency notices and the FL test guide. Host-tested status stays false until a real result is recorded. The Native plugin workflow now packages its tested binaries automatically and uploads a separate candidate artifact; failed jobs must not emit a successful candidate.

On main only (push/manual dispatch), a separate least-privilege publish job downloads the tested Windows artifact, verifies SHA256 and publishes v0.2.0-alpha.1 as a prerelease with EXE+VST3/source archives. It requires both native matrix jobs to succeed, never runs for pull requests and never replaces an existing alpha. Build jobs have read-only repository permissions; only the publish job can write releases. Until that workflow succeeds, these notes are preparation and no Windows download exists.
